# One validator for every datatype that has none (validator-catalog)

Date: 2026-11-25. Owner: Franco Pestilli. Status: approved approach (A).

## Why

116 of the 140 brainlife.io datatypes have no validator. A validator checks uploaded files and
hands them to the archiver; without one, the datatype cannot be uploaded through the UI, and CLI
uploads are archived unchecked. Franco asked for a validator wherever one is missing.

## How validators work today (warehouse-next `POST /dataset/finalize-upload`)

- If `datatype.validator` is set, warehouse submits that service (`validator`, `validator_branch`)
  as a task. Its `config.json` maps each uploaded file id to `../<upload task>/upload/<filename>`,
  and `_outputs[0]` carries the datatype id, datatype tags, tags and meta.
- The validator must link every file into `output/<filename or dirname>` (that directory is what
  gets archived) and write `product.json` with `errors`, `warnings`, `meta` (and optional `tags`,
  `datatype_tags`, `brainlife`). Any error fails the upload.
- Service names must start with `brainlife/validator-`; provenance code depends on the prefix.
- Without a validator, warehouse archives the upload directly.

## Approaches

A. **One validator driven by the catalog (chosen).** A single App checks any datatype using rules
   generated from the catalog (`datatypes/`). One repo, one container, new datatypes covered
   automatically.
B. One repo per datatype (as today): 116 repos and containers to maintain.
C. A now, dedicated validators later only where deep checks are needed.

## Design

- **Repo:** `brainlife/validator-catalog`, branch `main`. `main` runs
  `singularity exec -e docker://python:3.12-slim ./validate.py`. Python standard library only, so
  the container is small and nothing needs building.
- **Rules:** `rules.json` in the repo, generated by `bldt.py validator-rules` from the catalog:
  per datatype id, its name and files (`id`, `filename` or `dirname`, `required`, `format`). The
  format comes from the file name (`.nii.gz` -> nifti-gz, `.json` -> json, `.tsv` -> tsv, ...).
- **Checks** (standard library only):
  - presence of required files; directories exist and are not empty;
  - gzip streams decompress fully; NIfTI-1/2 headers (size, dims); JSON parses; TSV/CSV header
    and consistent column counts; FSL bvals/bvecs numeric with matching lengths (and matching the
    4th NIfTI dimension when both are present); magic bytes for MGH/MGZ, GIfTI, PNG, JPEG, SVG,
    PDF, HTML, HDF5, ZIP/TRX, MAT, EDF, BDF, FIF, BrainVision headers, MRtrix .tck, TrackVis .trk;
    Zarr directories hold `zarr.json` or `.zgroup`/`.zarray`.
- **Severity:** errors only for a missing required file, or a file that is unreadable or not in
  its format (corrupt gzip, invalid JSON, not a NIfTI). Everything else is a warning.
- **Fail-safe:** a bug in the validator never blocks an upload: any exception becomes a warning,
  and the files are still linked into `output/`.
- **Pass-through:** `product.json` copies meta, tags and datatype tags from `_outputs[0]`, so
  uploads keep their metadata.
- **Rollout:** set `validator: brainlife/validator-catalog`, `validator_branch: main` only on
  datatypes whose validator is empty, with an undo log (`bldt.py set-validator`). Pilot on a few
  datatypes; one end-to-end test upload before the rest.

## Not in scope

Replacing the 24 existing validators; normalising data (renaming, reorienting); deep
domain checks (FreeSurfer tree completeness, MEG channel sanity) — candidates for C later.
